# AGENTS.md

本文件指导后续编码代理在本仓库中实现和维护 Guarded Coding Harness。

## 项目目标

在不重写、复制或 monkey patch `smolagents` 核心的前提下，为
`smolagents.ToolCallingAgent` 增加一层可恢复的、确定性的治理层：

- 模型继续负责理解任务、选择工具和决定下一步。
- 程序负责参数与权限门禁、执行边界、运行状态、审计、恢复和最终验收。
- 首个交付范围只包含两类仓库任务：**代码理解**和**测试修复**。
- 模型声称“已完成”不构成成功证据；成功必须由程序检查工作区、测试结果和审计记录后判定。

当前仓库处于脚手架阶段，`docs/`、`src/`、`tests/` 可能为空。不得在实现和测试落地前，
把设计目标写成“已实现功能”。

## 技术栈

- Python 3.10+，优先使用 pyenv 管理的环境中开发和验证。
- 使用 pip 和 `requirements.txt` 管理依赖；如拆分开发依赖，仍需提供明确的统一安装入口。
- `smolagents` 是 Agent 执行框架，应使用其公开 API；所依赖版本必须在依赖文件中约束并在文档记录。
- pytest 用于测试。
- Ruff 用于 lint 和格式检查。
- 配置优先使用 YAML 或等价的声明式格式；配置必须加载后校验，不能信任任意字典。

## 强制架构边界

### 1. 保留 smolagents 的决策循环

- `ToolCallingAgent` 继续负责模型交互、工具选择和 ReAct 循环。
- 通过公开可组合点接入治理层，例如受控工具包装器、轻量子类和 harness 编排器。
- 不复制 Agent 类，不修改 site-packages，不依赖私有方法/属性，不用 monkey patch 改变工具执行路径。
- 如果必须覆盖公开执行方法，只做薄适配，并把门禁与副作用实现放在独立模块中；在 `docs/decisions.md`
  记录版本兼容性和升级验证方式。
- `step_callbacks` 可用于观测，但绝不能作为唯一安全门禁。

### 2. 唯一执行入口

- 所有可能访问仓库、启动进程、修改状态或触发审批的调用，必须经过 harness 的唯一 runtime/gateway 入口。
- 模型只提交候选工具名和参数；程序在每次执行前重新解析、校验、授权和执行。
- 展示给模型的可用工具白名单不等于执行授权；执行时必须再次检查。
- `ToolCallingAgent` 可能并发生成多个工具调用。默认串行执行写文件、进程和审批相关操作；
  并发只允许用于明确只读、彼此独立且有上限的调用。审计顺序必须稳定，审批不得因并发被重复消费。
- 内置 `final_answer` 不访问仓库，但其输出仍须经过模型之外的最终验收。

### 3. 门禁失败关闭

- 参数校验失败、状态损坏、审批不可用、审计无法写入或验收无法执行时，默认拒绝，不能降级为放行。
- 用 Pydantic `extra="forbid"` 或等价方式拒绝模型注入未声明字段。
- 工具注册信息至少包含名称、描述、输入 schema、风险等级、所需权限、超时、重试策略和是否幂等。
- 审批必须绑定工具名、规范化参数、目标工作区、运行 ID 和任务；参数或目标变化后原审批失效。
- 审批一次性消费。重放、过期、跨运行、跨工作区或已被撤销的审批均拒绝。
- 拒绝结果应作为有界、结构化的工具 observation 返回模型，不得伪造成功结果。

## 仓库与进程安全

- 每次运行只允许一个明确的仓库根目录。解析相对路径后必须做规范化，并用 `Path.resolve()` 或
  等价机制处理符号链接；对尚不存在的路径，展开最近已存在祖先后再判断包含关系。
- 不能只用字符串前缀判断路径。拒绝 `..` 逃逸、绝对路径越界、符号链接逃逸和大小写/分隔符绕过。
- 禁止读取 `.env`、密钥、令牌、凭据等敏感文件；禁止写入 `.git/`、依赖目录和任务配置声明的
  只读文件。若需要允许例外，必须使用窄范围的显式 allowlist。
- 命令使用 argv 数组和 `shell=False` 启动，不把模型字符串直接拼接成 shell 命令。
- 可执行文件和测试命令来自经过校验的任务配置或固定 allowlist；不能让模型任意指定解释器、shell
  包装或可执行路径。
- 子进程固定 `cwd` 到工作区，使用最小环境变量，剔除密钥类变量；设置输出上限、超时和进程组终止策略。
- 超时只代表“本地已停止等待”，不代表外部副作用没有发生。非幂等写或命令超时后必须标记结果不确定，
  禁止盲目自动重试。
- 任何重试只允许用于只读或明确幂等、且前一次确定未产生副作用或结果可安全重放的操作。

## 状态、审批、审计与恢复

- 每次任务运行必须有稳定且唯一的 `run_id`/`trace_id`，记录任务类型、工作区、配置指纹、开始时
  工作区状态、预算、当前阶段和最终结果。
- 状态必须持久化且并发安全。优先使用带事务的 SQLite 或等价方案；不得只把恢复状态放在内存。
- 状态转移遵循明确状态机，例如 `running -> waiting_approval -> running -> completed/failed/blocked`。
  非法转移必须拒绝。
- 在可能产生副作用前持久化“即将执行”的记录，在执行后记录确定结果。进程崩溃后应能区分
  “未开始”“已成功”“明确失败”和“结果未知”。
- 恢复时重新校验工作区、审批、参数指纹和配置版本；不能仅凭旧的 `running` 标记自动重放写操作。
- 审计是追加式事实记录，不是模型对话摘要。至少记录门禁决定、审批生命周期、工具开始/结束、
  退出码、超时、错误码、工作区指纹和最终验收结果。
- 放行和拒绝都要审计；“门禁关闭”也要留下显式记录。记录必须先脱敏再落盘或返回模型。
- 不得在日志、审计或错误信息中保存 API Key、令牌、密码或敏感环境变量值。

## 最终验收

模型输出不是验收判据。harness 在 Agent 停止后独立执行任务验收。

### 代码理解

- 只允许产生任务声明的文档交付物，不能修改目标仓库源码。
- 检查交付物存在、路径合法、内容非空、引用文件和行号可验证。
- 用工作区 diff/status 验证没有越界修改。
- 文档中的结论必须能追溯到实际读取过的代码；没读到的内容不能补写成确定事实。

### 测试修复

- 运行前记录基线，至少保存测试命令、开始时的 diff/status、退出码和失败摘要。
- 已有测试默认只读；只有任务配置显式允许的目录才能新增测试。
- 修复后使用同一验收命令复跑。最终成功以退出码和测试报告为准，不以模型自述为准。
- 检查改动是否限制在任务允许范围内，已有测试是否被修改、删除、跳过或弱化。
- 如果存在隐藏测试或项目特定验收条件，只能由程序执行；不要向 Agent 暴露隐藏用例细节。
- 测试命令不可用、超时、无输出但退出码异常或结果不确定时，不得判为成功。

任务元数据应声明工作区、允许/禁止路径、交付物、测试命令、预算、审批策略和验收规则。
不要在多个任务模块中散布硬编码任务名；任务知识的唯一权威来源应写入 `docs/` 中的设计或配置文档。

## 文档规范

- 本项目所有需求、设计、决策、任务拆解、测试计划和运维说明统一放在 `docs/`。
- 根目录 `README.md` 只做入口概览，并链接到 `docs/README.md`；不要把完整设计复制回根目录。
- `docs/README.md` 是文档索引。新增、移动或删除文档时同步更新索引。
- 评估或实施改动前，先读取 `docs/README.md`，再按改动范围加载相关文档；若当前没有文档，
  不要虚构既有约定，应在需要时先建立最小设计基线。
- 外部行为、安全边界、持久化格式、审批语义或任务契约发生变化时，更新对应设计/决策/测试文档。
- `docs/` 不保存密钥、临时聊天记录、源码镜像或运行产物。

## Python 与测试约定

- 遵循 PEP 8 和 PEP 257；公共 API、复杂安全判定和恢复逻辑必须有类型标注和清晰 docstring。
- 使用 `pathlib.Path`、`dataclass`/Pydantic 模型和上下文管理器表达边界，避免裸字典在模块间漂移。
- 异常必须保留稳定错误码和可操作信息；不要用宽泛 `except Exception: pass` 吞掉执行或审计失败。
- 默认测试必须离线、确定、可重复；模型调用用 fake/mock，不消耗真实额度，不访问真实网络。
- 必测安全边界包括：schema 注入、路径穿越、符号链接逃逸、越权工具、审批参数篡改/重放/过期、
  并行写冲突、命令超时、输出截断、敏感信息脱敏、审计写失败、崩溃恢复和最终验收拒绝。
- 测试通过前不得宣称功能完成。测试不能只覆盖 happy path。

## 完成标准

一次改动只有在以下条件都满足时才可交付：

1. 没有改写或侵入 `smolagents` 核心。
2. 所有仓库副作用经过唯一治理入口，失败关闭。
3. 新行为有覆盖安全边界和恢复路径的自动化测试。
4. lint、格式检查和测试通过，且命令与结果可复现。
5. 相关 `docs/` 已更新，文档、配置和实现契约一致。
6. 最终验收由程序证据驱动，而不是模型自述驱动。
